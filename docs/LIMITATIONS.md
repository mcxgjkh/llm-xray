# 限制与常见问题

本页集中说明 LLM-Xray 做不到什么、为什么，以及常见问题怎么处理。如果某个面板看起来“不对”，
先在这里找对应条目。方法原理见 [INTERPRETABILITY.md](INTERPRETABILITY.md)。

## 1. 根本限制：LM Studio 不暴露内部张量

LM Studio 的 HTTP API 只提供文本、采样参数、统计信息与可选的 `top_logprobs`。它不提供：
隐藏状态、逐层激活、注意力矩阵、MLP 输出、KV 缓存内容，也不提供 logits 全量分布。

因此，在 LM Studio 模式下，凡是需要读取模型内部的东西（注意力、Tuned Lens、残差、稀疏特征、
隐状态投影），LLM-Xray 都只能通过一个独立的替代模型近似。这不是实现偷懒，而是接口边界。项目把
边界显示出来（`surrogate` 徽标、`same-weights` 标记），而不是把近似包装成真实。

v1.1.0 增加了另一条路径：原生精确模式在 LLM-Xray 进程内直接运行一个本地 HF 模型，生成与观测
来自同一次前向，probe 的 `surrogate=false`。这解决的是“内部张量不可得”，但仅针对你加载的那个
本地模型；它并不改变 LM Studio 的接口边界，也不是 LM Studio 里 8B 模型的内部状态。

## 2. 替代模型不是同一个模型

- 默认透镜模型是 `Qwen/Qwen2.5-0.5B-Instruct`，而 LM Studio 对话模型通常是
  `deepseek-r1-distill-llama-8b`。两者架构、层数、词表、训练数据都不同，注意力模式与表示空间
  不可直接对应。
- 面板展示的是“另一个模型如何处理同一段文本”。它可以提示一般性的语言现象，但不能说明
  DeepSeek-R1 内部发生了什么。
- 不同 tokenizer 会导致 `context.tokens` 与 LM Studio 的 Token 切分不一致，对比时注意对齐。
- 原生精确模式下，生成和观测是同一个本地模型，因此 probe 是同一模型的精确张量；但如果你要比较
  LM Studio 的 8B 模型，仍需把相同权重加载到原生通道（并解决内存问题，见第 12 节）。
- `same-weights` 也需要透镜模型与 LM Studio 实际加载的量化/权重一致；文件名相同不代表数值完全
  相同（例如 LM Studio 侧可能使用不同的量化格式）。

## 3. DeepSeek-R1 的思考内容

- reasoning 内容作为 `kind="reasoning"` 的独立事件到达，对话窗默认折叠，不应与回答正文混为
  一谈。
- 思考内容同样消耗 Token、同样计入用量与上下文；它也可能被采样参数影响。
- 概率云与透镜面板会覆盖 reasoning Token；分析时先确认当前步骤的 `kind`。
- 推理模型的思考内容不是“模型的真实意图”，它只是模型输出的一部分；不要把它当成可靠的
  解释来源。
- 如果思考内容被截断或折叠，回放与 JSONL 中仍然保留，可展开核对。

## 4. 为什么概率云只有 top-k

- 后端向 LM Studio 请求 `top_logprobs=12`，只能拿到 top-12 候选（具体数量受接口与模型支持
  情况影响）。
- 模型真实分布是完整词表上的分布，top-k 之外的项可能仍有不可忽略的概率。LLM-Xray 显示的是
  截断后重新归一化的视图，不能当作完整分布。
- 已生成 Token 若不在 top-k 内，概率显示 `—`，不会伪造数值。
- 因此：比较“第一个候选与第二个候选的差距”是可靠的；比较“某候选的绝对概率”要谨慎，因为
  归一化分母被截断了。
- 前端用同一组 raw top-k 重算采样参数，保证拖动滑块时的一致性，但这仍然只是 top-k 子集上的
  重算，不能恢复被截断的候选。

### 4.1 LM Studio 可能完全不返回 top_logprobs

部分 LM Studio 版本、模型配置或流式接口（尤其 `/v1/responses`）在实际响应中不返回
`top_logprobs`，此时概率云没有任何候选。v1.1.0 的检测与提示：

- 前 5 个回答 Token 都没有 top-k 时，前端收到 `status(scope=runtime, state=no_logprobs)`，
  显示“LM Studio 未返回 top_logprobs；概率云为空，可切换原生精确模式”。
- 当前会话的 `capabilities.logprobs` 被标记为 `false`，回放时也能看出这次会话没有概率数据。
- 这不影响 Token 文本、TTFT、tok/s 与用量统计；只是少了概率云与词级候选。
- 要拿到完整概率与内部张量，可切换到原生精确模式（第 12 节），或尝试 LM Studio 中其他
  接口/模型配置。该提示不是错误，不会自动降级或重发请求。

## 5. KV 缓存是估算

- LM Studio 不公开 KV 缓存的实际内容与内存布局；`kv` 事件中的 `bytes`、`bytes_per_token`
  是按模型层数、KV 头数、head_dim、dtype 与当前 Token 数**推算**的。
- `KVInfo.estimated` 为 `true` 时，表示数值来自配置推算；显存占用还受框架、量化、对齐、碎片
  影响，实际值可能不同。
- KV 图用于观察增长趋势和容量余量，不用于精确容量规划。

## 6. MoE 与 SAE 未内置

- 默认透镜模型与默认原生模型都是 dense 因果语言模型；MoE 路由、专家激活不在 v1.1.0 的观测范围内。
- 稀疏特征默认使用 `feature-probe`：取 MLP top-k 神经元并用 `lm_head` 方向解码出标签，
  这不是 SAE，也不具备 SAE 的特征解耦性质。
- 若自行安装 `sae_lens` 并配置与透镜模型匹配的 checkpoint，可以通过适配器接口替换，界面才
  标注 `sae`。应用不附带任何 SAE 权重，也不会自动下载。
- 没有匹配 checkpoint 的“SAE 结果”不具备解释价值。

## 7. 显存与 CPU 竞争

- 透镜通道与 LM Studio 争抢同一台机器的内存、显存与 CPU。LM Studio 往往已经占用了大部分
  显存，透镜再申请 GPU 内存可能导致 LM Studio 卸载模型或生成变慢。
- 默认策略是透镜 CPU 2 线程、低优先级；这降低了干扰，但也让透镜数据更新变慢。
- 原生精确模式不走 LM Studio，但会在后端进程内占用大量内存与 CPU。生成期间同一时间只允许
  一个原生会话；与 LM Studio 同时运行会互相拖慢，建议切换引擎后在设置页卸载另一边。
- 生成期间透镜队列落后时，旧探测会被丢弃，只保留最新一步；因此某些步骤可能没有 probe。
- 若机器性能有限，建议关闭透镜，只使用 LM Studio 的概率云与性能指标，或改用 0.5B 原生模式。
  详见 [USAGE.md 第 17 节](USAGE.md#17-低配置电脑性能建议)。

## 8. 模型未加载时的错误

- 启动应用或读取模型列表**不会**加载模型；如果 LM Studio 没有加载模型，发送请求时才会报错。
- 连接超时不会被当成“接口不支持”而降级，而是直接报 `LMSTUDIO_UNREACHABLE`，避免在模型
  加载期间反复无效请求。
- 只有 HTTP 400/404/405 或明确的 "unsupported parameter" 才会触发接口降级；降级到无
  logprobs 的接口后，概率云将没有候选数据，界面会提示能力缺失。
- 模型加载中也可能表现为错误或空响应，稍候重试即可。

## 9. 采样参数只影响“下一步”

- 已经生成的 Token 由 LM Studio 用当时的参数采样，无法追溯修改。
- 拖动采样滑块改变的是：前端基于 raw top-k 的重新归一化显示，以及下一次请求的参数。
- 界面用“下一 Token 生效”标注。做对照实验时请固定参数并重新发起会话。

## 10. 其他已知限制

- UMAP 投影来自当前观测模型（替代透镜或原生精确模型），最多 256 点，每 8 个 Token 重新拟合；
  坐标不能跨模型、跨会话比较，也不代表全局语义距离。
- 回放依赖已保存的会话数据；`data/` 被清理后无法恢复。
- 导出 JSONL 包含输入与输出，分享前请检查敏感信息。
- 后端只监听 `127.0.0.1`，没有多用户、鉴权或远程访问设计，不适合作为对外服务。
- demo 模式的数据是合成的，只用于界面演示。
- 指标采样间隔约 1.5 秒，GPU 数据依赖 `nvidia-smi`；没有 NVIDIA 驱动或子进程失败时为 `null`。
- 界面文案与文档可能滞后于并行开发中的实现；`docs/SPEC.md` 仍是 v1.0.0 契约，v1.1.0 增量以
  `CHANGELOG.md`、`docs/API.md` 与 `docs/ARCHITECTURE.md` 为准。

## 11. 512 Token 截断已修复（v1.1.0）

- v1.0.0 的默认 `max_tokens` 是 512，且界面没有调整入口，长回答会在 512 处停止，看起来像模型
  自己结束。v1.1.0 将默认值改为 4096，并在采样面板与设置页增加“最大输出”滑块（256 到 8192）。
- 旧版本保存在浏览器本地存储里的 512 或未设置值，会在升级后第一次启动时一次性迁移到 4096；
  之后以用户选择为准。
- 修复的是“应用默认上限”，不是模型能力：即使调大滑块，LM Studio 仍可能因为模型上下文窗口、
  服务端配置或显存不足而提前结束；原生精确模式还受本机内存与模型最大上下文限制。
- 旧会话的 JSONL 里记录的 `sampling.max_tokens` 仍是当时的值，回放时显示的是历史参数，不会改写。

## 12. 原生精确模式的内存与速度限制

- 原生精确模式在 CPU 上以 float32 加载权重，不下载、不量化。默认 0.5B 需要约 2-3 GB 内存
  （加载峰值更高），首次加载约 20-30 秒；8B 的 FP32 权重约 32 GB，普通 16GB 机器无法加载，
  因此“原生跑 8B”在 v1.1.0 不现实。
- 当前不支持 `load_in_4bit`：请求会被明确拒绝，因为原生通道需要精确保留隐藏状态与注意力。
- 同一时间只允许一个原生生成会话，第二个请求返回 `BUSY`。生成期间在设置页加载/卸载模型也会
  被拒绝。
- CPU 推理速度显著低于 LM Studio 的 GPU 推理；tok/s 取决于 CPU 核数与模型大小。建议用 0.5B
  做观测，用 LM Studio 做长文生成。
- 原生模式的 `same_weights` 只在你加载的本地权重与 LM Studio 当前模型一致时才有意义；文件名
  相同不代表量化一致。
- 原生模型必须已经在本地（`models/lens/`、HF 缓存或绝对路径），应用不会下载；首次使用请运行
  `scripts/fetch_lens_model.ps1`。

## 13. 导出保存在 WebView2 中的行为

- 桌面版通过 pywebview 的 `js_api` 调用系统保存对话框，把 JSONL 写到用户选择的位置；取消对话框
  不会写入文件，页面底部会显示“已取消导出”。
- 普通浏览器标签页（例如用 `--browser` 启动或开发服务器）没有原生桥，使用 Blob 下载；某些
  WebView2/浏览器策略会拦截普通下载，这正是 v1.0 导出“点了没反应”的原因。
- 如果桌面版仍然没有反应：确认启动的是 `python desktop\launcher.py` 而不是 `--browser`；
  查看页面底部提示与 `data/server.log` 是否有前端错误；确认导出接口本身返回 200。
- 导出成功提示会显示保存路径（桌面版）或文件名（浏览器版），约 7 秒后自动消失。

## 14. 常见问题（FAQ）

### 为什么打开应用后看不到任何透镜数据？

透镜通道默认关闭，且需要单独的依赖与模型文件。先在界面开启透镜开关，或调用
`POST /api/lens/load`。状态面板会显示 `loading` / `ready` / `error`。

### 为什么顶栏显示 LM Studio 不可达，但 LM Studio 明明开着？

检查本地服务器是否启动、端口是否为 1234、是否监听 `127.0.0.1`。可在浏览器访问
`http://127.0.0.1:1234/v1/models` 验证。防火墙或代理也可能拦截本机回环请求。

### 为什么概率云里没有我生成的这个词？

它在 top-k 之外，概率显示 `—`。这不是 bug，原因见第 4 节。

### 概率云完全是空的，怎么办？

先看对话窗是否出现“LM Studio 未返回 top_logprobs”的提示。部分 LM Studio 版本/流式接口不返回
top-k，应用会标记会话 `logprobs=false`。可以切换顶栏引擎到“原生精确”（需要本地 Qwen 0.5B），
或调整 LM Studio 的接口/模型配置后重试。原因见第 4.1 节。

### 为什么生成到 512 Token 就停了？

这是 v1.0.0 的默认上限，v1.1.0 已修复：默认 4096，采样面板有“最大输出”滑块。若升级后仍停在
512，检查是否在跑旧构建，或本地存储迁移是否被禁用；详见第 11 节。

### JSONL 导出点了没有反应？

v1.0.0 在 WebView2 中依赖普通浏览器下载，可能被策略拦截。v1.1.0 桌面版改为系统保存对话框，
浏览器版回退 Blob；导出结果会在页面底部提示。若仍无反应，确认使用桌面启动器并检查
`data/server.log`，详见第 13 节。

### 原生精确模式为什么这么慢？能跑 8B 吗？

原生模式在 CPU 上以 float32 逐 Token 前向，速度取决于 CPU 与模型大小；0.5B 可用，1.5B 明显变慢，
8B 的 FP32 权重约 32 GB，普通 16GB 机器无法加载，因此不建议。需要长文快速生成时用 LM Studio。
详见第 12 节。

### 下载透镜/原生模型失败怎么办？

脚本会依次尝试 Hugging Face、`hf-mirror.com`，再回退 ModelScope；也可以手动把模型文件放到
`models/lens/`。应用本身不会联网下载，网络失败不影响 LM Studio 通道与演示模式。

### Tuned Lens 一直显示 Logit Lens？

首次需要后台校准，语料是项目文档与记忆库。v1.1.0 会把校准结果缓存到 `data/cache/`，之后启动
直接加载缓存，不再重复训练；如果从未完成，检查透镜是否处于 `ready` 状态与 CPU 占用。

### agreement 很高，是不是说明解释是对的？

不是。agreement 只表示 Tuned Lens 在该层对校准语料的 top-1 预测与真实最终 logits 的接近程度，
不衡量正确性或因果性。

### 注意力热图能证明模型“关注”了某段文字吗？

不能证明因果。注意力权重是读取强度的启发式指标，可能被后续层补偿或冗余。头分类也是启发式。

### 模型响应很慢，是 LLM-Xray 拖慢的吗？

先关闭透镜通道、原生模型与 3D 视图再对比。LM Studio 模式下 WebSocket 开销很小；主要开销来自
透镜前向、UMAP 拟合和浏览器 3D 渲染。原生模式本身就是 CPU 推理，慢是预期行为。指标面板的
tok/s 可用来对比开关前后的差异。

### 可以把透镜/原生模型设成 DeepSeek-R1 吗？

可以，但需要本机有对应 HF 权重，显存/内存需求显著增加。原生模式跑 8B 在 16GB 机器上不现实；
LM Studio 模式把透镜指向相同权重时会标记 `same-weights`，即便如此，量化差异仍可能造成数值偏差。

### 数据会不会上传？

不会。应用只访问本机 LM Studio；除用户主动运行的模型下载脚本外，不需要联网。LM Studio 自身
的网络行为由 LM Studio 控制。详见 [ARCHITECTURE.md 第 9 节](ARCHITECTURE.md#9-隐私与本地性)。

### 支持 macOS 或 Linux 吗？

v1.1.0 面向 Windows，桌面外壳使用 pywebview + Edge WebView2。后端与前端理论上跨平台，但
启动器、脚本与文档按 Windows 编写；其他平台需要自行适配，不在本版本承诺范围内。
