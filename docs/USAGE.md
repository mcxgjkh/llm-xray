# 使用说明

本文是 LLM-Xray v1.1.0 的完整使用说明，覆盖安装、启动、三种推理引擎、界面、采样参数、各类观测
面板、原生精确模式、回放导出与性能调优。命令按 Windows PowerShell 编写。

若只需要最短路径，见 [README 快速开始](../README.md#快速开始windows)。遇到报错先看
[限制与常见问题](LIMITATIONS.md)。

## 1. 环境要求

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10/11 x64 | 桌面外壳使用 pywebview + Edge WebView2 |
| Python | 3.11 | 后端与启动器 |
| Node.js | 22 | 仅在开发、构建前端时需要 |
| LM Studio | 0.4.x | 默认运行时；真实 Token 与采样参数来源 |
| 内存 | 16 GB 起 | 8B 量化模型 + WebView2 + 可选透镜 |
| 显存 | 按 LM Studio 模型需求 | LM Studio 模式会占用显存 |
| WebView2 | 已安装 | 安装 LM Studio 或 Edge 时通常已具备 |

可选的替代透镜与原生精确模式还需要 PyTorch 与 Transformers，见第 13、14 节。没有安装这两组
依赖时，应用仍可使用 LM Studio 通道的 Token、性能指标与回放。

## 2. 准备 LM Studio

1. 打开 LM Studio，在模型管理器中下载并加载 `deepseek-r1-distill-llama-8b`（量化版本自选）。
2. 进入 `Developer` 页签，启动本地服务器。
3. 确认监听地址为 `http://127.0.0.1:1234`，并允许本机端口访问。
4. 在浏览器打开 `http://127.0.0.1:1234/v1/models`，能看到模型条目即说明服务器可用。

注意：

- LLM-Xray 启动、读取模型列表、切换界面时**不会**加载模型，也不会替 LM Studio 加载模型。
- 只有你在界面点击发送后，才会向 LM Studio 发起一次生成请求。
- 模型未加载时发送会得到错误提示；先回到 LM Studio 加载模型。
- LM Studio 地址可通过环境变量 `LMSTUDIO_BASE_URL` 修改，默认
  `http://127.0.0.1:1234`。
- 部分 LM Studio 版本或流式接口不会返回 `top_logprobs`。如果连续几个回答 Token 都没有候选，
  应用会提示“LM Studio 未返回 top_logprobs；概率云为空”，并标记该会话的 `logprobs=false`。
  此时可改用原生精确模式（第 14 节），或换用会返回 logprobs 的接口/模型配置。

## 3. 启动应用

### 3.1 发布版（推荐）

```powershell
python desktop\launcher.py
```

启动器会在子进程中启动本地后端（默认 `127.0.0.1:8765`），等待健康检查通过后打开 pywebview
窗口；关闭窗口时后端随之退出。选项：

| 参数 | 作用 |
| --- | --- |
| `--port 8765` | 修改后端端口 |
| `--browser` | 用系统浏览器打开而不是原生窗口（适合调试） |
| `--no-window` | 只启动后端，不打开窗口 |
| `--reload` | 开发时把 reload 传给 uvicorn（仅后端） |

如果提示“未找到前端构建产物”，先执行第 3.3 节的构建。启动器日志写入 `data/server.log`。

### 3.2 开发版

```powershell
powershell -ExecutionPolicy Bypass -File scripts\dev.ps1
```

脚本会同时启动：

- 后端 uvicorn：`http://127.0.0.1:8765`
- Vite 开发服务器：`http://127.0.0.1:5173`

终端会打印两个地址；开发时在浏览器打开 5173。修改前端代码由 Vite 热更新，修改后端代码由
uvicorn 自动重载（脚本默认开启 `--reload`）。按 `Ctrl+C` 结束前端并停止后端。

### 3.3 生产构建

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
python desktop\launcher.py
```

`build.ps1` 会做版本一致性检查并在 `apps/desktop/dist` 生成前端静态产物；它不会自动执行
PyInstaller 打包（打包需要人工核对资源路径）。

### 3.4 演示（demo）模式

没有 LM Studio 或还没加载模型时，可以在对话窗空状态点击“演示模式”按钮（需要先点观测台右上角的
“新建对话”回到空状态）。演示数据由后端本地合成，用于预览界面与图表；它不是真实模型输出，
不能用于分析真实模型行为。对话窗会标注“演示”。

### 3.5 原生精确模式

原生精确模式在 LLM-Xray 自己的后端进程内运行本地 HF 因果模型，生成 Token 与观测用的隐藏状态、
注意力来自同一次前向。它不需要 LM Studio，但需要：

```powershell
pip install -r backend\requirements-lens.txt
powershell -ExecutionPolicy Bypass -File scripts\fetch_lens_model.ps1
```

启动应用后，在顶栏把“引擎”切到 `原生精确`；如果是第一次使用，到设置页的“原生精确模型”面板
点“加载原生模型”。默认解析 `models/lens/` 下的 `Qwen/Qwen2.5-0.5B-Instruct`，也可以填写其他
本地模型目录或模型 ID（必须已在本地，后端不会自动下载）。0.5B 在 CPU 上首次加载约 20-30 秒，
生成速度明显慢于 LM Studio；8B 级别模型不适合普通内存机器，详见第 14 节。

### 3.6 只启动后端

调试接口时可以直接：

```powershell
python desktop\launcher.py --no-window
```

然后用浏览器访问 `http://127.0.0.1:8765`，或直接用 REST/WebSocket 客户端连接
`ws://127.0.0.1:8765/ws`。

## 4. 首次使用流程

1. 启动 LM Studio 服务器并加载模型（或跳过，直接使用原生精确模式）。
2. 启动 LLM-Xray。顶栏“引擎”选择默认是 `LM Studio`；连接状态应显示“LM Studio 在线”。
3. 确认模型下拉框选中 `deepseek-r1-distill-llama-8b`，模型状态标签显示“已加载”。
4. （可选）在设置页填写系统提示；或在对话窗点开“采样”调整参数（包括最大输出）。
5. （可选）在记忆宫殿页确认索引状态；默认只展示召回结果，不自动注入。
6. 发送第一条消息。观察：
   - 对话窗中的思考过程默认折叠，回答逐 Token 输出；
   - 顶栏与性能条显示 TTFT、tok/s、Token 数、上下文、GPU 与显存；
   - 观测台的概率云随每个 Token 更新；若 LM Studio 不返回 top-k，会出现 no-logprobs 提示；
   - LM Studio 模式下开启替代透镜后，注意力、透镜阶梯、残差、稀疏特征与向量空间出现数据，
     并带“替代透镜”标记；原生精确模式下这些数据带“精确张量”标记。
7. 生成结束后，会话写入 `data/sessions/`，可以在时间回放页逐 Token 回看。
8. 需要离线分析时，用“导出 JSONL”按钮或 `GET /api/sessions/{id}/export` 下载数据。

## 5. 界面布局与操作

界面由左侧窄导航轨、顶栏、中部工作区、右侧对话窗与底部时间轴组成。

### 5.1 左侧导航轨

图标按钮，悬停显示名称，从上到下依次是：

| 页面 | 内容 |
| --- | --- |
| 观测台 | 概率云、透镜阶梯、解码树、注意力热图、残差贡献、KV 映射、稀疏特征 |
| 注意力 | 焦点层的逐头注意力与头功能分类 |
| 向量空间 | 3D 语义投影、隐状态摘要、稀疏特征、KV 映射 |
| 记忆宫殿 | 本地记忆检索、分数明细、索引管理、KV 映射 |
| 时间回放 | 当前会话步骤表、历史会话、导出 |
| 技术文档 | 应用内阅读 `docs/*.md`（使用说明、架构、可解释性、接口、边界、版本） |
| 设置 | 连接、替代透镜、采样默认值、观测与界面、本地记忆、关于 |

导航轨底部显示当前版本号。

### 5.2 顶栏

顶栏包含两列选择器：左侧“引擎”（LM Studio / 原生精确 / 演示），右侧随引擎切换显示 LM Studio
模型列表或原生精确模型列表；旁边是连接/加载状态、当前会话 id 与生成耗时。原生精确模式下顶栏
显示“原生精确就绪 / 模型加载中 / 模型未加载”，观测台数据带“精确张量”标记。对话窗折叠后，
顶栏右侧会出现展开按钮。

### 5.3 右侧对话窗

- 拖拽对话窗左侧的分隔条可以调整宽度（约 320 到 680 像素，窗口足够宽时），宽度会被记住。
- 点对话窗标题栏的折叠按钮可收起对话窗；设置页也有“收起对话窗”和“重置对话窗宽度”。
- 标题栏还提供“导出 JSONL”按钮；导出时按钮会显示导出中状态，完成后弹出提示（桌面版显示保存路径）。
- 对话窗包含消息、输入框、采样折叠面板与声化开关。
- 生成中可随时停止；已生成的 Token 与会话数据保留。
- DeepSeek-R1 的思考内容单独显示、默认折叠，不计入回答正文；生成完成后可复制回答。
- 透镜未加载/加载中/加载失败时，对话窗会显示可点击的引导条（CTA）；LM Studio 不返回
  top_logprobs 时会出现切换到原生精确模式的提示。

### 5.4 底部时间轴

每次生成结束后，时间轴按步显示 Token；点击某一步会把观测台、注意力与向量空间切到该步，
回放模式可逐步前后移动。

## 6. 采样参数与“下一 Token 生效”

对话窗的“采样”折叠面板和设置页都可以调整以下参数，默认值见
`apps/desktop/src/types.ts`：

| 参数 | 默认值 | 界面范围 | 作用 |
| --- | --- | --- | --- |
| temperature | 0.7 | 0.05 到 2 | 缩放 logits，越高分布越平 |
| top_p | 0.95 | 0.05 到 1 | 核采样，保留累计概率不超过 p 的候选 |
| top_k | 40 | 1 到 100 | 只保留概率最高的 k 个候选 |
| repetition_penalty | 1.05 | 1 到 1.5 | 按最近 64 个 Token 的出现次数惩罚重复 |
| max_tokens | 4096 | 256 到当前模型 max_context_length | 单次生成上限；仍受已加载上下文限制 |
| seed | null | 协议字段，界面未提供输入 | 可选随机种子，取决于 LM Studio 支持情况 |

`max_tokens` 在 v1.0.0 中硬编码为 512，长回答会被截断；v1.1.0 已改为默认 4096 并提供滑块。
旧版本保存在浏览器本地存储里的 512 或未设置值会在第一次启动 v1.1.0 时自动迁移到 4096，
之后以你的选择为准。注意：即使把滑块拉大，LM Studio 仍可能受模型上下文窗口、服务端配置或
显存限制提前结束生成。

关键行为：

1. 后端把模型原始的 top-k log-prob 发给前端；参数修改后，前端用同一组 raw 分布重新计算
   Softmax、Top-P、Top-K 和重复惩罚，因此拖动滑块不会重新请求模型，概率云即时更新。
2. 参数修改**只影响显示重算与下一次请求**。当前已经生成的 Token 是 LM Studio 用旧参数采样的，
   无法追溯更改。界面标注“显示参数即时重算概率云；实际采样参数在下一个请求生效”。
3. 如果已生成 Token 不在当前 top-k 候选中，概率显示 `—`，而不是伪造一个数值。
4. 后端无法获得完整词表分布，只能获得 `top_logprobs=12` 内的候选，因此概率云是 top-k 截断后的
   视图。详见 [LIMITATIONS.md](LIMITATIONS.md)。

## 7. 观测台

观测台把一次生成的关键视图放在同一页：

- **概率云**：每个 Token 一帧，显示该步 top-k 候选、概率、排名，选中的实际 Token 高亮，并显示
  选中概率与该步熵。概率由 Canvas/SVG 自绘，不引入图表库。熵低表示分布集中，不代表回答正确。
- **透镜阶梯**：显示 3 个代表性层（均匀分布并包含最后一层）的 Tuned Lens（校准后）或 Logit Lens
  （校准前）top-k，以及该层 top-1 与校准目标的一致率 `agreement`。点某一层可以把它设为
  焦点层，供注意力热图使用。
- **解码树**：把已生成步骤组织成树，点击节点跳到该步；回放模式下与时间轴联动。
- **注意力热图**：行是当前 Token，列是上下文 Token，显示焦点层的注意力分配；可切换层与头。
- **残差贡献**：铜色为 attention 分支、橄榄色为 MLP 分支的 signed logit 贡献柱，上方同时给出
  各层 L2 范数。
- **KV 映射**：按块显示 KV 缓存占用与容量估算。
- **稀疏特征探针**：当前 Token 激活的 MLP 神经元方向与强度，标注“非 SAE”。
- **观测注记**：明确标注数据来源。LM Studio + 替代透镜显示“替代透镜”；原生精确模式显示
  “精确张量”，表示生成与观测来自同一次前向。

## 8. 注意力页

- 选择焦点层与头（含“平均”），查看该层注意力行与完整热度矩阵。
- 头分类为启发式统计：`previous-token`、`local`、`syntactic`、`entity`、`global`、`diffuse`，
  不是人工标注的功能标签。
- 为控制带宽，实时数据只带焦点层的逐头行；其他层只有平均行。完整多层矩阵在回放时通过 REST
  读取。
- 注意力权重表示读取强度，不表示因果重要性；详见 [INTERPRETABILITY.md](INTERPRETABILITY.md)。

## 9. 向量空间页

- **3D 语义投影**：Prompt 与生成 Token 的最终层隐状态（最多 256 点）经 UMAP 投影，每 8 个
  Token 后台重新拟合；不足 8 点用 PCA，再不足用确定性伪投影。鼠标拖拽旋转、滚轮缩放、
  悬停查看 Token 与步骤。LM Studio 模式下点来自替代透镜模型；原生精确模式下点来自你加载的
  本地模型。
- **隐状态摘要**：当前步 16 维降采样的条形图。
- **稀疏特征**：与观测台相同的探针结果，展示更多条目。
- **KV 映射**：同观测台的 KV 占用图。
- 语义距离只来自当前观测模型；重新拟合后坐标会变化，不能跨模型、跨刷新或跨会话比较。

## 10. 记忆宫殿

- 数据源是项目根目录 `memory/*.md`，按段落切块（约 320 字，48 字重叠）。
- 检索是混合检索：字符 3-gram BM25 + LM Studio embedding 余弦；embedding 不可用时退化为纯 BM25。
- 混合分数默认 `0.55 * cosine_norm + 0.45 * bm25_norm`；结果展示余弦、BM25、混合分与命中词。
- 页面上的开关：
  - “生成时检索”：发送消息时执行召回并展示；
  - “注入提示”：把召回内容写入 system prompt（默认关闭，避免额外 Token）；
  - 刷新图标：重建索引。
- 修改 `memory/` 文件后需要重建索引（界面按钮或 `POST /api/rag/reindex`）。
- embedding 调用只在索引/查询时发生，走本地 LM Studio 的 `/v1/embeddings`，不经过云端。

## 11. 时间回放与 JSONL 导出

### 11.1 回放

历史会话保存在 `data/sessions/`（每个会话一个 `.jsonl` 与一个 `.meta.json`）。时间回放页：

- 当前会话步骤表列出步号、Token、熵、概率、是否有 probe；点击行或按 `Enter` 跳到该步；
- “历史会话”面板可打开已落盘的会话；
- 回放不会重新请求 LM Studio，也不会重新运行透镜模型；
- 缺失的 probe 会在需要时通过 REST 补取，补取失败不影响其他数据。

### 11.2 JSONL 导出

每条步骤一行 JSON，包含 Token 与 probe 快照，适合用 Python/pandas 做离线分析。

桌面版（pywebview 窗口）点击“导出 JSONL”会打开系统保存对话框，直接把文件写到用户选择的位置；
普通浏览器标签页没有原生桥，会回退为 Blob 下载。两种方式都会在页面底部显示导出成功、取消或失败
的提示；取消保存不会写入文件。WebView2 中如果仍然没有反应，请先确认用的是桌面启动器而不是
`--browser` 模式，并查看 `data/server.log` 是否有前端错误。

也可以直接调用接口导出：

```powershell
Invoke-WebRequest http://127.0.0.1:8765/api/sessions/<session-id>/export -OutFile session.jsonl
```

导出字段见 [API.md](API.md)。JSONL 里包含模型输出与你的输入，分享前请检查是否含敏感内容。

## 12. 设置页

- **推理引擎**：在 LM Studio / 原生精确 / 演示之间切换，当前引擎会显示在标签上。切换后顶栏的
  模型选择器同步变化；历史会话仍按当时的引擎保存。
- **LM Studio 连接**：只读服务地址、选择模型、刷新模型列表；显示架构、量化、最大上下文与
  推理通道优先级。发送前不会加载模型。
- **原生精确模型**：填写本地 HF 模型目录或模型 ID，点“加载原生模型”或“卸载并释放”；显示状态、
  设备、权重关系与线程。默认解析 `models/lens/` 下的 Qwen2.5-0.5B，后端以 `local_files_only`
  加载，不会自动下载。
- **替代透镜**：输入本地模型 ID 或绝对路径，点“加载透镜”或“卸载并释放”；显示状态、设备、
  已校准层数与权重关系（替代模型 / 与主模型相同）。同样以 `local_files_only` 加载。
- **采样默认值**：温度、Top-P、Top-K、重复惩罚、最大输出滑杆与系统提示；“下一次请求生效”。
- **观测与界面**：CRT 覆膜、熵声化、生成时检索记忆、允许透镜采样四个开关；重置对话窗宽度、
  收起对话窗。
- **本地记忆**：文档数、片段数、混合检索方式、注入状态；可重建索引。
- **关于**：版本、桌面外壳、前端/后端技术栈、数据目录、网络与模型调用说明。

## 13. 可选透镜通道

透镜通道默认关闭，只在 LM Studio 模式下配合使用。启用步骤：

```powershell
pip install -r backend\requirements-lens.txt
powershell -ExecutionPolicy Bypass -File scripts\fetch_lens_model.ps1
```

然后在设置页点“加载透镜”（或调用 `POST /api/lens/load`），再打开“允许透镜采样”开关。
默认模型为 `Qwen/Qwen2.5-0.5B-Instruct`，CPU 2 线程、进程优先级低于正常。下载脚本会把权重放进
`models/lens/`，应用会自动解析该目录；也可在设置页填写任意本地 HF 因果语言模型路径。应用不会
自动下载模型，加载时也不会自动联网。

Tuned Lens 首次使用需要在后台对本地文档做一次岭回归校准，结果缓存到
`data/cache/tuned_lens_<model>.pt`。v1.1.0 起会直接加载并复用已有缓存，不再每次启动重复校准；
校准完成前面板显示 Logit Lens。

如果 `huggingface.co` 不可达，脚本会依次尝试 `https://hf-mirror.com`；也可以先设置
`$env:HF_ENDPOINT='https://hf-mirror.com'`。两者都失败且模型 ID 是 `owner/name` 形式时，脚本会
回退到 ModelScope 直接文件接口下载（需要系统 `curl.exe`，Windows 10/11 自带）。下载失败不会影响
LM Studio 通道与演示模式。

如果你把透镜模型指向与 LM Studio 相同的 HF 权重，界面会标记“与主模型相同”。这是 LM Studio
模式下获得“同一模型”内部张量的路径，代价是额外显存/内存与更慢的生成，需自行评估。

## 14. 原生精确模式（in-process，CPU 较慢）

原生精确模式不经过 LM Studio：后端在自己的进程内用 Transformers 加载一个本地 HF 因果模型，
逐 Token 生成；每个 Token 的隐藏状态、注意力、Tuned Lens、残差、稀疏特征与投影都来自同一次
前向，probe 标记 `surrogate=false`、`same_weights=true`。界面显示“精确张量”，表示这些张量与
生成它的模型是同一个，而不是替代模型的猜测。

使用步骤：

1. 安装依赖并获取模型（与透镜通道共用一份权重）：

```powershell
pip install -r backend\requirements-lens.txt
powershell -ExecutionPolicy Bypass -File scripts\fetch_lens_model.ps1
```

2. 启动应用，在顶栏把“引擎”切到“原生精确”。
3. 如果需要换模型，在顶栏“精确模型”下拉框选择，或在设置页填写本地目录后点“加载原生模型”。
   默认 `Qwen/Qwen2.5-0.5B-Instruct`；可选 `deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B`（必须
   已在本地）。
4. 发送消息。首个 Token 前需要编码提示词并建立 KV cache，CPU 上等待时间明显长于 LM Studio。

性能与限制：

- 默认 CPU 推理，2 线程、低优先级；0.5B 首次加载约 20-30 秒，生成速度以个位数到十几 token/s
  计，取决于 CPU。
- 同一时间只允许一个原生生成会话；另一个请求会收到 `BUSY`。
- 8B 级别模型在普通 16GB 内存机器上不现实（FP32 权重就远超内存），不建议在原生模式运行；
  0.5B/1.5B 是当前现实范围。
- 当前不支持 4bit 加载：请求 `load_in_4bit` 会明确报错。原生通道用 CPU float32 保证隐藏状态与
  注意力精确。
- 生成与观测共用的模型是你加载的本地权重，不是 LM Studio 中的 8B 模型；只有加载相同权重时
  才可跨通道比较。
- 原生模式不运行替代透镜 worker；采样参数（温度、Top-P、Top-K、重复惩罚、最大输出）同样生效，
  概率来自同一次前向的 logits。
- 上下文长度受本地模型配置与本机内存限制；长会话可能触发 KV cache 压缩/重建，速度会下降。

如果只是想看 LM Studio 模型的真实 Token 与速度，用 LM Studio 模式；需要完整内部张量且能接受
CPU 开销时，用原生精确模式。两者不要同时用于同一次比较实验。

## 15. CRT 与声化

- CRT 覆膜是纯装饰层，关闭后完全不会消耗渲染资源；可在设置页或对话窗底部开关。
- 熵声化把熵与选中概率映射为 Web Audio 声音（低熵清脆高音、高熵低频噪声），默认关闭，需要一次
  用户手势后才会启动。使用耳机时注意音量。
- 这两项都不会改变模型行为，也不会产生额外网络请求。
- 开启系统 `prefers-reduced-motion` 时，动画自动降级。

## 16. 操作方式

- 输入框：`Enter` 发送，`Shift+Enter` 换行。
- 顶栏“引擎”下拉框切换 LM Studio / 原生精确 / 演示；右侧模型下拉框选择对应引擎的模型。
- 拖拽对话窗分隔条调整宽度；折叠按钮或设置页收起对话窗；“导出 JSONL”在对话窗标题栏。
- 点击左侧导航切换页面；点击观测台内的层、头、步骤切换焦点。
- 步骤表、解码树节点支持点击；聚焦后可用 `Enter`（解码树还支持空格）选择。
- v1.1.0 没有全局快捷键；回放使用底部时间轴的播放/暂停与上一步/下一步按钮。

## 17. 低配置电脑性能建议

按收益从高到低：

1. 不要同时开启 LM Studio 与原生精确模型：两者都会占满内存/CPU。用完原生模式后在设置页
   “卸载并释放”。
2. 关闭“允许透镜采样”或在设置页卸载透镜：这是 LM Studio 模式下最大的额外开销。
3. 原生精确模式优先用 0.5B；1.5B 已明显变慢，8B 不建议在普通机器上尝试。
4. 不要同时拖动 3D 视图、切换多层注意力或频繁点步骤；高频交互会与生成渲染竞争主线程。
5. 关闭声化与 CRT 覆膜，减少音频线程与额外重绘。
6. 关闭“生成时检索”，避免每轮都做 embedding 查询。
7. 指标采样保持默认约 1.5 秒，不要改得更密；nvidia-smi 是子进程，失败时返回空值而不阻塞。

性能预算与线程模型见 [ARCHITECTURE.md](ARCHITECTURE.md)。

设置决定，与本应用无关。删除 `data/` 与 `models/` 目录前请确认没有需要保留的会话或模型文件。

## 19. 排错速查

| 现象 | 先检查 |
| --- | --- |
| 顶部提示 LM Studio 不可达 | LM Studio 是否启动 Local Server、端口是否 1234、模型是否加载 |
| 发送后立刻报错 | 模型名是否与 LM Studio 中一致；模型是否处于加载中 |
| 生成在 512 Token 处停止 | 是否仍在使用 v1.0 的本地存储旧值；v1.1.0 默认 4096，可在采样面板调“最大输出” |
| 概率云为空、没有候选 | LM Studio 是否返回 top_logprobs；看对话窗 no-logprobs 提示，或切换原生精确模式 |
| JSONL 导出没有反应 | 是否桌面启动器窗口；看底部导出提示与 `data/server.log`；浏览器模式走 Blob 下载 |
| 启动器提示缺少 dist | 先运行 `scripts\build.ps1`，或在开发时用 `scripts\dev.ps1` |
| 透镜面板一直 loading | 是否安装 requirements-lens、模型是否已在本地、设置页是否已点“加载透镜” |
| 设置页加载透镜失败 | 模型 ID 是否在本地缓存或路径是否存在；后端不会自动联网下载 |
| 校准很慢 | 首次需在后台训练各层 translator；CPU 越弱越慢，可先用 Logit Lens；缓存后不再重复 |
| 原生模型加载失败 | 是否安装 torch/transformers；模型是否在本地；8B 是否超出内存 |
| 原生模式很慢 | CPU 推理的正常现象；换 0.5B、关闭其他占用 CPU 的任务，或改用 LM Studio |
| 原生模式提示 BUSY | 已有一个原生生成在进行；停止或等待结束后再发送 |
| 3D 点云静止 | UMAP 重新拟合的节流设计，或点数不足时退化为 PCA |
| 某一步没有 probe | 透镜队列落后时旧探测会被丢弃，属正常现象 |
| 中文 Token 乱码 | v1.1.0 已修复 Qwen 等 tokenizer 的解码；确认运行的是新构建 |
| 导出文件打不开 | 确认是 JSONL（一行一个 JSON），不是 JSON 数组 |
| 下载模型失败 | 检查网络；脚本会尝试 hf-mirror 与 ModelScope，也可手动下载到 `models/lens/` |

更多问题与解释见 [LIMITATIONS.md](LIMITATIONS.md)。接口细节见 [API.md](API.md)。
