LLM-Xray 技术文档

暖色的本地 LLM 观测台。LM Studio 实时遥测、可选的替代透镜、以及进程内 原生精确通道并排显示：概率云、注意力、Tuned Lens、残差与 3D 语义投影，全部在本机完成， 不上传会话。

Windows 10/11 · pywebview + WebView2 · FastAPI · React / TypeScript / Three.js
LM Studio 0.4.x · Python 3.11 · Node.js 22

打开应用（8765） 开发版界面（5173） 使用说明（Markdown）

项目概览

LLM-Xray 把三种数据来源分开显示：LM Studio 提供的真实 Token 流、 top_logprobs、TTFT、tok/s 与用量；一个可选的独立小模型提供的 替身内部状态；以及一个可选的进程内原生精确通道， 生成与观测共用同一次前向（surrogate=false）。

LM Studio 模式下的透镜通道默认关闭，开启后也不会影响真实 Token 流，所有替身数据都带 surrogate 标注；原生精确模式的数据带“精确张量”标注，表示它与生成 来自同一个本地模型。

真实遥测

来自你正在使用的 LM Studio 模型：Token、top-k 概率、TTFT、tok/s、结束原因与用量。

替代透镜

来自另一个小模型：内部状态的可视化近似，用于观察趋势，不是目标模型的内部真相。

原生精确

在进程内运行本地 HF 模型，生成与张量同一次前向；默认 Qwen2.5-0.5B，CPU 较慢。

本地优先

只监听 127.0.0.1，无云 API，不上传会话；模型、记忆库与缓存都在本机目录。

必须先知道的边界

LM Studio 的 HTTP API 不暴露隐藏状态、逐层注意力或 MLP 输出，部分流式响应甚至不返回 top_logprobs。LM Studio 模式下的注意力热图、Tuned Lens、残差、稀疏特征与 3D 点云来自一个独立小模型（默认 Qwen/Qwen2.5-0.5B-Instruct），不能当作目标 模型的内部状态。原生精确模式解决的是“本地模型张量可得”，但它运行的是你加载的模型， 不是 LM Studio 里的 8B 模型，除非显式加载相同权重。

进入应用

  1. 启动 LM Studio，加载 deepseek-r1-distill-llama-8b，开启本地服务器 （默认 http://127.0.0.1:1234）；或跳过，使用原生精确模式。
  2. 在项目根目录运行 python desktop\launcher.py（发布版）或 scripts\dev.ps1（开发版）。
  3. 顶栏“引擎”选择 LM Studio、原生精确 或 演示。 原生精确首次使用需在设置页点“加载原生模型”。
  4. 用桌面窗口访问；开发版可直接打开 http://127.0.0.1:5173。 本页顶部的按钮在服务未启动时会显示连接失败，先启动应用即可。

快速开始（Windows）

前置条件

  • Windows 10/11，Edge WebView2 运行时（安装 LM Studio 或 Edge 时通常已具备）。
  • Python 3.11；Node.js 22（仅开发与构建前端时需要）。
  • LM Studio 0.4.x，本地服务器默认端口 1234。
  • 可选透镜/原生精确通道需要 PyTorch 与 Transformers，见下文。

1. 准备 LM Studio

在 LM Studio 中加载 deepseek-r1-distill-llama-8b，打开 Developer 页签启动本地服务器，确认地址为 http://127.0.0.1:1234。可以在浏览器访问 http://127.0.0.1:1234/v1/models 验证。启动 LLM-Xray 或读取模型列表不会加载 模型，只有点击发送才会发起生成。若实际流没有返回 top_logprobs，概率云会为空， 界面会提示切换到原生精确模式。

2. 安装依赖

python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r backend\requirements.txt
npm --prefix apps\desktop install

3. 启动开发环境

powershell -ExecutionPolicy Bypass -File scripts\dev.ps1

后端 127.0.0.1:8765，Vite 127.0.0.1:5173，脚本会打印两个地址。

4. 构建并运行桌面版

powershell -ExecutionPolicy Bypass -File scripts\build.ps1
python desktop\launcher.py

启动器会启动本地后端（默认 127.0.0.1:8765），等待健康检查通过后打开原生窗口。 常用参数：--port、--browser、--no-window、 --reload。启动器日志在 data/server.log。

可选：启用替代透镜 / 原生精确

pip install -r backend\requirements-lens.txt
powershell -ExecutionPolicy Bypass -File scripts\fetch_lens_model.ps1

应用不会自动下载模型；下载脚本会尝试 Hugging Face、hf-mirror 与 ModelScope，权重默认放入 models/lens/。替代透镜在 LM Studio 模式下使用；原生精确模式复用同一份本地 权重，在顶栏切换引擎并在设置页加载。Tuned Lens 首次校准结果会缓存到 data/cache/，之后直接复用。

没有 LM Studio 的时候

在对话窗空状态点击“演示模式”（需要先新建对话回到空状态），用后端本地合成数据查看布局 与图表。演示数据不是真实模型输出，不能用于分析。应用内“技术文档”页可直接阅读 docs/*.md。

采样参数与概率云

参数默认值界面范围作用
temperature0.70.05 到 2缩放 logits，越高分布越平
top_p0.950.05 到 1核采样，累计概率不超过 p 的候选
top_k401 到 100只保留概率最高的 k 个候选
repetition_penalty1.051 到 1.5按最近 64 个 Token 的出现次数惩罚重复
max_tokens4096256 到 8192，步进 256单次生成上限；仍受模型上下文限制
seednull协议字段，无输入框可选随机种子，取决于 LM Studio 支持情况

v1.0.0 的默认上限是 512，长回答会被截断；v1.2.0 改为 4096 并提供“最大输出”滑块。旧版本 保存在本地存储里的 512 或未设置值会一次性迁移到 4096。即使调大上限，LM Studio 仍可能受 模型上下文窗口或显存限制提前结束。

后端把模型原始 top-k log-prob 发给前端；修改参数后，前端用同一组原始分布 重算 Softmax、Top-P、Top-K 与重复惩罚，不需要重新请求模型，所以滑块响应是即时的。

下一 Token 生效

参数修改只影响显示重算与下一次请求。已经生成的 Token 由 LM Studio 用旧参数 采样，无法追溯修改，界面会明确标注“下一 Token 生效”。若已生成 Token 不在当前 top-k 内，概率显示 —，不会伪造数值。

概率云每个 Token 一帧，显示 top-k 候选、概率、排名、熵与选中 Token 概率。概率是截断后重新 归一化的结果：top-k 之外的词不可见，因此不要比较绝对概率，只能比较候选之间的相对结构。

观测面板

观测台

一页同时放下概率云、透镜阶梯、解码树、注意力热图、残差贡献、KV 映射与稀疏特征探针。 “观测注记”会明确标注数据来源：LM Studio + 替代透镜，或原生精确张量。

  • 概率云：每步 top-k 候选、概率、熵与选中 Token；拖动采样参数时即时重算。
  • 透镜阶梯：3 个代表性层的 Tuned Lens 或 Logit Lens top-k（含最后一层），点层号设为焦点层。
  • 解码树：按步组织已生成 Token，点击节点跳到该步，回放时与时间轴联动。
  • 注意力热图：焦点层的上下文分配，可切换层与头。
  • 残差贡献：铜色为 attention、橄榄色为 MLP 的 signed logit 贡献柱，附 L2 范数。
  • KV 映射：按块显示 KV 缓存占用与容量估算。
  • 稀疏特征探针：当前 Token 激活的 MLP 神经元方向与强度，标注“非 SAE”。

注意力页 surrogate exact

行是当前 Token，列是上下文 Token。可切换焦点层、单个头或平均行，并查看头功能分类： previous-token、local、syntactic、 entity、global、diffuse。分类来自统计量启发式， 不是真值标签。实时数据只带焦点层的逐头行，其余层只有平均行。

Tuned Lens 与 Logit Lens surrogate exact

Tuned Lens 为每层训练一个仿射 translator，把该层隐藏状态翻译到最终隐藏状态，再应用最终 LayerNorm 与 lm_head 解码。首次使用以 docs/、memory/ 与 README/CHANGELOG 中的短句为校准语料，用岭回归闭式解训练，结果缓存到 data/cache/tuned_lens_<model>.pt，之后启动直接复用；校准完成前显示 Logit Lens 作为对照，并显示该层 top-1 与校准目标的一致率 agreement。原生精确模式下 这些张量来自生成模型的同一次前向，不再是替代模型。

向量空间页 surrogate exact

3D 语义投影收集当前观测模型 Prompt 与生成 Token 的最终层隐状态（最多 256 点），后台每 8 个 Token 重新拟合 UMAP；不足 8 点用 PCA，再不足用确定性伪投影。页面同时提供当前步 16 维隐状态摘要、稀疏特征与 KV 映射。局部邻域有意义，坐标不能跨模型、跨刷新或跨会话比较。

记忆宫殿

数据源为 memory/*.md，混合检索 = 字符 3-gram BM25 + 本地 LM Studio embedding 余弦（默认权重 0.55 / 0.45）。召回结果展示余弦、BM25、混合分与命中词；两个开关分别控制 “生成时检索”和“注入提示”，默认只展示不注入。页面可重建索引，并显示文档数、片段数与 KV 映射。

时间回放与 JSONL 导出

会话以每步一行写入 data/sessions/<id>.jsonl，另存 <id>.meta.json。时间回放页可查看当前步骤表与历史会话，点击步骤或按 Enter 跳转；回放不重新请求 LM Studio。导出接口 GET /api/sessions/{id}/export 返回 JSONL，一行一个步骤（含 probe 快照）。 桌面版通过 pywebview 原生保存对话框写文件，浏览器版回退 Blob 下载，页面底部会显示结果提示。

原生精确模式

原生精确模式在 LLM-Xray 后端进程内用 Transformers 加载本地 HF 因果模型，逐 Token 生成。 Token、top-k、隐藏状态、注意力、Tuned Lens、残差与投影来自同一次前向， probe 标记 surrogate=false，界面显示“精确张量”。这正是它和替代透镜的根本 区别：不是另一个模型对同一段文本的猜测，而是生成 Token 的那个模型自己的内部状态。

项说明
引擎切换顶栏“引擎”选择“原生精确”，设置页加载/卸载模型并查看状态
默认模型Qwen/Qwen2.5-0.5B-Instruct，复用 models/lens/ 本地权重
依赖PyTorch + Transformers + 本地权重；应用不自动下载
设备与速度CPU 2 线程、float32；0.5B 首次加载约 20-30 秒，生成明显慢于 LM Studio
并发同一时间只允许一个原生生成会话，冲突返回 BUSY
模型规模0.5B 可用，1.5B 明显变慢；8B 的 FP32 权重约 32 GB，普通 16GB 机器不现实
量化当前不支持 4bit 加载；原生通道用 CPU float32 保证张量精确
精确张量不等于因果解释

“同一模型、同一次前向”只保证数据来源精确，不保证注意力权重、头分类、稀疏特征或残差 归因能解释输出因果。它们仍是启发式与近似方法，解读边界见 INTERPRETABILITY.md。

性能建议

观测不应改变被观测对象。LM Studio 模式的 WebSocket 开销很小；主要开销来自替代透镜前向、 UMAP 拟合与 3D 渲染；原生精确模式本身就是 CPU 推理，慢是预期行为。按收益从高到低：

  1. 不要同时开启 LM Studio 与原生精确模型；两种引擎用完在设置页卸载。
  2. 关闭“允许透镜采样”，或在设置页卸载透镜：这是 LM Studio 模式下最大的额外开销。
  3. 原生模式优先用 0.5B；1.5B 已明显变慢，8B 不建议在普通机器上尝试。
  4. 生成期间不要拖动 3D 视图或频繁切换层与步骤；高频交互会与生成渲染竞争主线程。
  5. 关闭声化与 CRT 覆膜；开启系统 prefers-reduced-motion 时动画自动降级。
  6. 关闭“生成时检索”，避免每轮都做 embedding 查询；透镜就绪后再打开。

后端指标约 1.5 秒采样一次，GPU 通过 nvidia-smi 子进程获取，失败返回 null 而不阻塞。生成期间后端不做同步磁盘写，会话完成后落盘。

运行时与观测通道

+----------------------+     HTTP / SSE      +---------------------------+
|  LM Studio 0.4.x     | <----------------> |  FastAPI backend          |
|  127.0.0.1:1234      |  responses (first)  |  backend/xray/            |
|  real tokens/probs   |  chat/completions   |  - LM Studio adapter      |
+----------------------+  embeddings (RAG)   |  - sessions / replay      |
                                             |  - RAG / metrics          |
+----------------------+   in-process       |  - native_bridge (exact)  |
|  native exact model  | ----------------->  +-------------+-------------+
|  local HF weights    |  token + probe                    |
|  CPU, float32        |  (surrogate=false)                | WebSocket /ws
+----------------------+                                   | JSON frames
                                                           v
+----------------------+   optional local PyTorch  +---------------------------+
|  surrogate lens      | -----------------------> |  React UI                 |
|  Qwen2.5-0.5B, CPU   |  hidden / attention /     |  pywebview + WebView2     |
|  default unloaded    |  tuned lens / residual    |  Canvas / SVG / Three.js  |
+----------------------+  features / UMAP          +---------------------------+

三种引擎互斥：LM Studio、原生精确、演示。LM Studio 模式下替代透镜可选且不阻塞生成； 原生精确模式不运行替代透镜 worker，probe 与生成来自同一次前向；demo 用合成数据。原生通道 同一时间只允许一个生成会话，避免进程内两个前向同时占满 CPU/内存。

LM Studio 适配优先级

  1. POST /v1/responses：SSE，stream=true， include=["message.output_text.logprobs"]，top_logprobs=12， store=false。唯一能同时拿到文本与 top_logprobs 的官方路径。
  2. POST /v1/chat/completions：stream=true， logprobs=true，top_logprobs=12，额外传 top_k 与 repeat_penalty。
  3. POST /api/v1/chat：原生 SSE，无 logprobs，只用于文本与推理流。

只有在 HTTP 400/404/405 或明确的 "unsupported parameter" 时才降级；连接超时不降级，直接报 LMSTUDIO_UNREACHABLE，避免在模型加载期间反复无效请求。启动应用与读取模型列表 不会加载模型。即使接口成功，实际流也可能没有 top_logprobs：前 5 个回答 Token 都没有 top-k 时发送 status(scope=runtime, state=no_logprobs) 并标记会话 logprobs=false，不会自动重发请求。

可解释性方法

方法分两类数据来源：LM Studio 模式下的“替身观测”，以及原生精确模式下的“同一次前向”。 无论来源如何，它们能生成假设，不能直接给出因果结论。完整版见 INTERPRETABILITY.md。

Tuned Lens 与 Logit Lens

Tuned Lens 假设存在逐层仿射映射 h'_l = h_l @ W_l + b_l，把第 l 层隐藏状态 翻译到最终层坐标系，再应用最终 LayerNorm 与 lm_head 解码。translator 用岭回归 在本地校准语料上闭式求解。Logit Lens 省略 translator，直接把最终 LayerNorm 与 lm_head 套到中间层；浅层通常不可靠，作为对照基线保留。

agreement 是 Tuned Lens 在该层对校准语料的 top-1 预测与校准目标的 top-1 一致率（目标在最终输出空间解码），不是准确率、不是置信度，也不能跨模型比较。参考 AlignmentResearch/tuned-lens 与 Transformer Circuits Thread。

注意力

用 eager attention 与 KV cache 逐 Token 增量前向，捕获每个头对上下文的注意力行。注意力 权重只表示读取强度，不表示因果重要性；头分类是启发式统计，不是人工标注。参考 arXiv:1905.09418、arXiv:1906.04341。

残差贡献

分别捕获 attention/MLP 分支输出，计算 L2 范数，并把分支增量经最终 LayerNorm 的一阶近似 投影到词表方向，得到对当前选中 Token 的 signed logit 贡献。忽略 LayerNorm 非线性与后续层 交互，不能把数值相加当成完整 logit 分解。

稀疏特征与 UMAP

默认稀疏特征是 MLP 神经元探针（probe），不是 SAE；只有匹配 checkpoint 的 SAE 适配器才标注 sae。UMAP 只保留局部邻域结构，坐标每次重新拟合都会改变， 不能当作语义距离度量。UMAP 文档： umap-learn.readthedocs.io。

正确解读

可以做：同模型、同校准、同会话内比较趋势；用概率云判断解码分布形状；用 JSONL 做离线 统计；把面板当作假设生成器。

不要做：把替代模型结果说成目标模型内部状态；从注意力推断因果；用单层 top-1 词解释最终 输出；跨模型比较绝对值。

隐私与数据

  • 后端默认只监听 127.0.0.1，不提供公网访问、鉴权或多用户设计。
  • 应用不包含云 API 客户端；对话、会话、遥测与指标都不上传。
  • RAG embedding 调用本机 LM Studio 的 /v1/embeddings，不经过第三方服务。
  • 模型、校准缓存、会话与导出文件都在本机 data/、models/ 目录。
  • 原生精确通道以 local_files_only 读取本地权重，不联网、不自动下载。
  • 唯一的外部网络行为是用户显式运行模型下载脚本；应用不会自动下载模型。
  • LM Studio 自身的网络行为由 LM Studio 设置决定，不属于本应用控制范围。

限制与排错

核心限制

  • 接口边界：LM Studio 不暴露内部张量，替身观测不是目标模型内部状态。
  • top_logprobs 可能缺失：部分 LM Studio 流不返回 top-k，概率云为空；界面会 提示切换到原生精确模式。
  • 模型不同：默认透镜是 Qwen2.5-0.5B，与 DeepSeek-R1-distill-8B 不同架构、 不同词表；只有 same-weights 路径能拿到同一权重的数据。
  • 512 已修复：v1.2.0 默认最大输出 4096 并提供滑块；仍受模型上下文限制。
  • 原生 8B 不现实：CPU float32 下 8B 权重约 32 GB，普通 16GB 机器无法加载； 且当前不支持 4bit。
  • 概率云截断：只含 top-k（top_logprobs=12）候选，概率经过重新 归一化。
  • KV 是估算：按模型配置推算，estimated 为 true，不等同实际显存。
  • MoE / SAE 未内置：默认透镜是 dense 模型；稀疏特征是探针不是 SAE。
  • 资源竞争：透镜与 LM Studio 争内存、显存与 CPU；原生模式与 LM Studio 同时 运行也会互相拖慢。
  • 导出保存：桌面版用系统保存对话框，浏览器版用 Blob 下载；导出结果有提示。
  • 模型未加载：LM Studio 不会自动加载模型；原生模型也不会自动下载。
  • 参数时序：采样参数只影响显示重算与下一次请求。
